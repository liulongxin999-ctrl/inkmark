# 图片型 PDF → 可批注文字：完整操作指南

> 适用场景：PDF 的每一页都是一张图片，选中不了文字，墨读提示「没有文字层」。
> 目标：把它变成墨读里**可划线、可批注、可设术语、可搜索**的文字。

---

## 0. 核心原则：三档分流

不要试图把所有公式都变成 LaTeX，按这个规则分流，效果最好也最省事：

| 档位 | 内容 | 处理方式 | 在墨读里的效果 |
| --- | --- | --- | --- |
| 一档 | 能用普通文字表达的 | **纯文本**，不套 `$` | 最干净，完全可批注 |
| 二档 | 中等复杂度公式 | **LaTeX**（`$...$`） | 显示为源码，可选中、可批注、可搜索 |
| 三档 | 多行推导、矩阵、图、表 | **保留为图片** | 只显示 `〔图片〕` 占位符 → 回原版 PDF 看 |

另有一条铁律：**只转你真正精读的页**。整本转一遍既费时间，也很难逐条校对。

---

## 1. 先确认你的 PDF 是哪一类

| 类型 | 判断方法 | 处理难度 |
| --- | --- | --- |
| 文字型 | 用系统阅读器 `Ctrl+F` 能搜到正文词 | 直接导入墨读即可，无需本文档 |
| 图片型 | 搜不到任何正文词；墨读导入后提示"没有文字层" | 需要本文档的流程 |
| 混合型 | 能搜到一部分（常是页眉页脚或水印） | 同图片型，按图片型处理 |

**随手可做的自检**：在墨读里导入后看两处——
1. 顶部是否出现黄色提示「这份 PDF 似乎没有文字层」
2. 正文区是否只剩「第 N 页」的分页标记、中间没有内容

## 2. 环境准备

### 2.1 硬件门槛（MinerU 官方档位对照）

| 档位 | 模型引擎 | 模型体积 | 最低内存 | 加速器 |
| --- | --- | --- | --- | --- |
| `basic` 基础 | ONNX | 约 0.8 GB | 2 GB | 纯 CPU 即可 |
| `standard` / `advanced` | ONNX + llama.cpp | 约 2 GB | 8 GB | CPU 可以，**推荐 Vulkan** |
| `standard` / `advanced` | PyTorch + llama.cpp | 约 2 GB | 16 GB | 需要 GPU，8 GB+ 显存 |
| `standard` / `advanced` | PyTorch + vLLM/lmdeploy | 约 3 GB | 16 GB | 需要 GPU，8 GB+ 显存 |

**先查自己的配置**（Windows PowerShell）：

```powershell
(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB   # 内存
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores # CPU
nvidia-smi                                                          # 显卡与显存（有独显时）
python --version                                                    # Python 版本
```

对照结论：

- 内存 ≥ 8 GB 且能接受纯 CPU 跑 → 用默认安装 + `standard` 档
- 有 NVIDIA 显卡且显存 ≥ 8 GB → 可考虑装 GPU 版提速（Windows 需单独装 GPU 版 torch）
- Python 需满足 `>=3.10,<3.15`；若系统版本不符合，用 `uv python install 3.12` 让 uv 准备一个

### 2.2 安装（Windows PowerShell）

官方推荐用 `uv` 管理（本机还没装，先装它）：

```powershell
pip install uv
```

如果 `pip` 命令不在 PATH 里（提示"不是内部或外部命令"），但 Python 可用，就用：

```powershell
python -m pip install uv
```

也可以直接用官方一键脚本，或跳过 uv、用全局 pip 安装（见 <https://docs.astral.sh/uv/>）：

```powershell
python -m pip install "mineru>=4.0,<5"
```

然后安装 MinerU（**默认装法即可开箱即用**：小模型走 ONNX CPU，VLM 走 llama.cpp 的 Vulkan 模式，兼容性最好）：

```powershell
uv tool install --python 3.12 "mineru>=4.0,<5"
```

> 加 `--python 3.12` 是为了让 uv 自己准备一个干净的解释器环境，避免和系统里其它 Python 环境打架。
> 如果你的系统 Python 已经在 `>=3.10,<3.15` 范围内，也可以直接用；uv 报错时再执行 `uv python install 3.12`。

**可选：开启 NVIDIA GPU 加速**

```powershell
uv tool install --force "mineru[full]>=4.0,<5"
```

注意官方提示：**Windows 上的 GPU 版 torch 需要单独安装**，`[full]` 不一定开箱即用。所以建议**先跑默认装法**，觉得慢再折腾 GPU。

### 2.3 先探一下机器能力

```powershell
mineru --help
mineru version --json
mineru server status --json
```

`Supported Inputs` 支持 PDF 和图片；PDF 支持全部四个档位。

> 模型默认会下载到用户目录（约 2 GB）。想改缓存位置，用 `mineru config show` 查看当前配置项，具体键名以官方文档为准：<https://opendatalab.github.io/MinerU/zh/>

## 3. 第一步：圈定要转换的页码范围

**不需要手动切 PDF**——MinerU 自带页范围参数：

```powershell
--pages 1-10        # 只转第 1 到 10 页
--pages all         # 全部页
```

**推荐节奏**：先转**一章**（比如 60 页）试水，确认质量后再决定要不要继续。

---

## 4. 第二步：执行转换

### 4.1 推荐命令（无状态转换，导出 Markdown）

```powershell
mineru-kit parse "D:\教材\某本书.pdf" --pages 30-95 -o "D:\转文字\第2章.md" --tier standard
```

说明：

- `mineru-kit parse` 是**无状态转换**，默认处理全部页（用 `--pages` 限制范围）
- `-o` 指定输出文件；`--tier standard` 是官方建议的**常规阅读质量**
- 另一种 `mineru parse "x.pdf" --json` 是**文档库模式**，默认只处理前 10 页，适合"先看再继续"

### 4.2 四个档位怎么选

| 档位 | 特点 | 什么时候用 |
| --- | --- | --- |
| `flash` 极速 | 质量最低、最快 | 只想知道大概内容、做索引 |
| `basic` 基础 | 质量一般 | 资源紧张时兜底 |
| `standard` 标准 | **高质量，官方默认推荐** | **你的情况就用这个** |
| `advanced` 高级 | 难稿更好，最慢 | 排版特别复杂的页面 |

### 4.3 首次运行会发生什么

1. 自动下载模型（约 2 GB，视网速几分钟到十几分钟）
2. 逐个页面解析：版面分析 → 文字识别 → 公式识别 → 表格识别 → 还原阅读顺序
3. 输出结果文件

### 4.4 输出是什么

典型输出包括：

- **Markdown 主文件**：正文文字 + `$...$` 公式 + 表格 + 图片引用
- **图片目录**：页面里的插图、被判定为"不适合转文字"的复杂区域
- 可选的 JSON（结构化内容，含每块的坐标，便于核查）

MinerU 支持 9 种渲染目标：Markdown、HTML、**LaTeX**、DOCX、EPUB、PDF、Structured Content、Content List V1/V2。你只需要 Markdown。

### 4.5 在线/远程模式（不想装本地环境时）

```powershell
mineru parse "x.pdf" --remote
```

**注意**：`--remote` 会把文档上传到远程服务，涉及隐私，请自行确认是否接受。

## 5. 第三步：校验（最关键的一步）

考试用书里错一个符号，可能整道题都做错，所以这一步不能省。

### 5.1 高危字符清单（计算机网络尤其常见）

| 风险点 | 例子 | 为什么致命 |
| --- | --- | --- |
| 大小写 B / b | `Mbps`（兆比特）vs `MBps`（兆字节） | 差 8 倍 |
| 数字 0 与字母 O | `10^6`、`O(n)` | 复杂度与数值混淆 |
| 数字 1 与字母 l / I | `l`（长度） | 公式读错 |
| 希腊字母 ν / v、ρ / p | `ρ = λ/μ` | 公式整体变形 |
| 上下标嵌套 | `2^n`、`R_i`、`x_{i+1}` | 语义改变 |
| 分式范围 | 分子分母被截断 | 结果完全不同 |
| 单位幂与千进制 | `10^-6`、`kbit` | 数量级错误 |

### 5.2 五分钟抽查法

不想逐字校对的话，至少抽查这些位置：

1. **每个公式**是否完整（分子分母、根号覆盖范围、上下标）
2. **所有数值与单位**是否与原文一致
3. **例题与答案的编号**是否对得上
4. **表格**是否被拆碎了（表格是最容易出问题的）
5. 随机抽 3 段正文，逐字对比原文

### 5.3 双版本对照法（推荐）

1. 把 **Markdown 文字版**和**原 PDF** 都导入墨读（同一个书库里两个条目）
2. 读文字版时，凡是遇到公式或图表，切到原 PDF 用「原版页」看那一页
3. 这样可以做到：**正文用文字批注，公式和图表回原版核对**

### 5.4 发现问题怎么改

墨读的正文是从文件里读进来的，**正文不可编辑**，所以要改 Markdown 源文件：

1. 用记事本/VS Code 打开 `.md`
2. 直接修正错误
3. 在墨读里删除这本书，重新导入修正后的 `.md`

> 因此建议：**先转换 + 校验 + 修好，再导入墨读**，避免反复导入。

---

## 6. 第四步：导入墨读

1. 书库页把 `.md` 文件拖进去
2. 建议命名成 `书名（文字版）.md`，和原 PDF 区分开
3. **同时把原 PDF 也导入**，作为公式与图表的对照本

导入后你会看到两件事，都是预期行为：

- 公式显示为 LaTeX 源码（如 `\frac{L}{R}`），**它是文字，可以正常批注和搜索**
- 图片位置显示为灰色的 `〔图片〕` 占位符（墨读目前不渲染导入的图片）

---

## 7. 第五步：让公式真正好用

墨读现成的三件工具，正好补上"公式不能排版"的遗憾：

**① 把关键公式做成术语**

- 术语名：`发送时延公式`
- 定义：`\frac{L}{R}`（L 为数据块长度，R 为信道带宽）
- 之后全书凡是出现这个公式的相关讨论，都能从术语面板一键跳转；悬停即可看定义

**② 用标签建立体系**

`#公式` `#易错` `#计算题` `#真题` —— 笔记工作台可以按标签筛选，复习时只看某一类

**③ 用复习页抽卡**

把公式设成术语后，复习页会把"术语名"作为正面、定义（公式）作为背面，按遗忘曲线抽你背诵。

## 8. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页眉页脚混进正文 | 版面分析把页眉当正文 | 在 Markdown 里删掉，或改用 `advanced` 档 |
| 表格变成一堆短段落 | 表格被拆散 | 保留表格为图片，或手动用 Markdown 表格重写 |
| 例题编号错乱 | 阅读顺序还原不准 | 抽查时重点看编号；必要时用 `advanced` 档重转该章 |
| 转换很慢 | CPU 推理 + 页数多 | 用 `--pages` 缩范围；或装 GPU 版 |
| 导入后体积大、加载慢 | Markdown 很长 | 按章拆成多个文件导入 |
| 公式被误判成图片 | 版面分析把它当图形 | 说明该公式较复杂，正好归到三档里的"图片"档，回原版看 |
| `mineru` 命令找不到 | 装到了别的 Python 环境 | `uv tool list` / `pipx list --short` 查一下，必要时 `uv tool install --force` 重装 |

## 9. 时间预估

以 60 页的一章为例（本机 CPU 模式，`standard` 档）：

| 步骤 | 预计耗时 |
| --- | --- |
| 安装 + 首次下载模型 | 10–30 分钟（一次性） |
| 转换 60 页 | 视硬件，几十分钟量级 |
| 校验与修正 | 30–60 分钟（**不能省**） |
| 导入并开始批注 | 5 分钟 |

装好 GPU 版后转换会明显加快。

## 10. 备选方案（装不上或不想装时）

| 方案 | 适合 | 公式表现 |
| --- | --- | --- |
| **MinerU 远程模式** | 不想本地部署 | 同标准档 |
| **PaddleOCR / PP-StructureV3** | 中文识别，轻量 | 有公式模型，转 LaTeX |
| **Mathpix**（付费） | 公式要求最高 | 业内最强，按页收费 |
| **视觉大模型逐页转** | 只处理少量重点页 | 灵活，但需逐页调用、可能"编造" |
| **WPS / 福昕 / Acrobat 的 OCR** | 纯文字书 | 公式明显变差，不建议用于本书 |

---

## 11. 一句话总结

**只转你要精读的章节 → 用 `standard` 档转成 Markdown → 逐条校验公式与单位 → 导入墨读做文字批注 → 原版 PDF 留作公式与图表的对照本。**

公式能用普通文字写就用文字，需要保留结构的用 LaTeX，图和表回原版看——不要追求"全部公式都变成整齐的数学排版"。
